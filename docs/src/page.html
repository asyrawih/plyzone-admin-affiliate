Mulai di sini

Gambaran besar

Apa yang sebenarnya terjadi dari link dibagikan sampai komisi muncul.

Sistem ini kerjanya sederhana: admin ngajak orang main ke map kamu lewat link khusus. Orang yang masuk lewat link itu disebut spender. Setiap kali spender belanja (beli developer product pakai Robux, atau kirim donasi bagi-bagi), admin yang ngajak dapat komisi. Game kamu cuma perlu lapor ke server. Server yang ngitung.

Klik tiap kotak buat lihat detailnya.

Link dibuat otomatis di dashboard (menu Admins) untuk tiap admin dan tiap map. Bentuknya: https://www.roblox.com/games/start?placeId=…&launchData=ref_KODE. Admin tinggal copy dan sebar ke mana pun.

Admin juga punya halaman pribadi /a/<token> tanpa login, isinya saldo, daftar komisi, dan link share-nya.

Waktu player masuk lewat link itu, Roblox nyelipin teks ref_KODE ke LaunchData. AffiliateService membacanya saat PlayerAdded dan mengirim POST /ingest/join berisi UserId, username, kode tadi, plus ReferredByPlayerId kalau player masuk lewat undangan Roblox.

Server nyatet: "spender ini diajak admin X". Aturannya first-touch: yang dihitung admin pertama, selamanya. Player yang masuk tanpa link juga tetap dilaporkan (kodenya kosong) supaya tercatat sebagai spender organik.

Robux: di handler ProcessReceipt game (ReceiptService), satu panggilan AffiliateReport.Robux(info) setelah produk tersimpan. Hanya developer product yang dihitung, game pass tidak.

Bagi-bagi: setelah donasi tercatat di papan (DonationBoardService), satu panggilan AffiliateReport.Donation(event, userId, name). Kalau donaturnya lagi ada di server, UserId-nya ikut dikirim supaya cocok pasti.

Server cari siapa spender-nya, siapa admin pengajaknya, dan rate yang berlaku saat itu. Robux dipotong fee Roblox 30% dulu, dikonversi ke Rupiah, baru dikali persen komisi. Bagi-bagi langsung dikali persen komisi.

Hasilnya masuk ke buku besar (ledger) admin. Tiap bulan owner generate payout dan tandai sudah dibayar. Semua ini di luar game, kamu nggak perlu ngapa-ngapain lagi.

✓
Yang perlu kamu lakukan di game cuma tiga hal

Lapor saat player join, lapor saat ada pembelian Robux, lapor saat ada donasi bagi-bagi. Sisanya urusan server.

Pasang di Roblox · langkah 2

Alamat API & secret key

Alamat server ada di satu konstanta. Key tidak ditulis di script sama sekali, tapi dibaca dari Roblox Secret.

AffiliateReport · konstanta di atas
local BASE_URL = "https://affiliate.kelasmalam.app" -- alamat server, TANPA garis miring di akhir

Aturan alamat API

  • Harus https dan bisa diakses dari internet. Roblox nggak bisa memanggil localhost atau IP lokal.
  • Jangan pakai garis miring di akhir. Script menambahkan sendiri /ingest/join dan seterusnya.
  • Satu server bisa melayani banyak map. Tiap map punya key sendiri, jadi laporan otomatis tahu datang dari map mana.

Simpan key sebagai Roblox Secret

Ingest key (berawalan mk_, dari dashboard Config → Maps) disimpan di Creator Dashboard → experience kamu → Secrets. Dua nama secret:

  • AF: key map produksi. Dipakai di server live.
  • AF_STUDIO: key map tes. Dipakai hanya saat jalan di Studio, supaya data tes tidak jadi komisi produksi. Tidak ada AF_STUDIO = laporan mati di Studio, warn sekali, game jalan normal.

AffiliateReport membacanya lewat ApiAuth.affiliateKey(). Tambahkan fungsi ini di ServerScriptService.Server.ApiAuth kalau belum ada:

ApiAuth · tambahan
local HttpService = game:GetService("HttpService")
local RunService = game:GetService("RunService")

local affiliateCache: Secret? = nil
local affiliateWarned = false

-- Ingest key map afiliasi. nil = secret tidak terbaca → fitur afiliasi mati, game jalan normal.
function ApiAuth.affiliateKey(): Secret?
	if affiliateCache ~= nil then
		return affiliateCache
	end
	local name = if RunService:IsStudio() then "AF_STUDIO" else "AF"
	local ok, secret = pcall(HttpService.GetSecret, HttpService, name)
	if ok then
		affiliateCache = secret
		return secret
	end
	if not affiliateWarned then
		affiliateWarned = true
		warn(`[ApiAuth] secret {name} tidak terbaca; laporan afiliasi dimatikan`)
	end
	return nil
end

Nilai Secret bisa langsung dipakai sebagai header x-map-key di HttpService:RequestAsync, jadi key tidak pernah muncul sebagai string di script maupun di Output.

!
Key bocor? Rotate.

Dashboard → Config → Maps → Rotate key. Key lama langsung mati, semua request dengan key lama ditolak 401. Update nilai secret AF di Creator Dashboard; server yang sudah jalan perlu restart (atau tunggu server baru) karena key di-cache sekali per server.

Pasang di Roblox · langkah 3

Share link admin

Link inilah yang membuat sistem tahu player masuk lewat siapa.

Bentuk link yang dibuat dashboard untuk tiap admin:

format share link
https://www.roblox.com/games/start?placeId=123456789&launchData=ref_K7PQ2M
  • placeId: Place ID map kamu.
  • launchData=ref_K7PQ2M: kode referral admin, diawali ref_. Kode 6 huruf/angka, tanpa huruf yang mirip (0/O, 1/I).

Saat player klik link itu, Roblox membuka game dan mengisi player:GetJoinData().LaunchData dengan teks ref_K7PQ2M. AffiliateService membacanya dan mengirim ke server. Kamu nggak perlu mengurai kodenya di game, kirim mentah saja.

Hal yang sering bikin bingung

  • LaunchData cuma terisi kalau masuk lewat link atau undangan dari tombol "Undang teman". Join dari daftar game atau dari Studio: nilainya nil. Ini normal. Player tetap dilaporkan sebagai join biasa. Undangan dari menu sistem Roblox (tanpa LaunchData) tetap ditangkap lewat ReferredByPlayerId dan dicocokkan ke admin yang punya akun Roblox itu.
  • First-touch. Spender terikat ke admin pertama yang kodenya dia pakai, selamanya. Kalau dia masuk lagi lewat link admin lain, dicatat tapi tidak mengubah apa-apa.
  • Admin nggak bisa ngajak dirinya sendiri. Kalau admin punya Roblox user ID dan masuk lewat link-nya sendiri, dianggap self_referral dan diabaikan.
  • Kode nggak dikenal atau admin nonaktif tetap dicatat di riwayat, tapi tidak diatribusi. Bisa dicek di halaman Flow dashboard.
  • Server toleran: ref_k7pq2m, REF-K7PQ2M, atau ada spasi di ujung tetap dibaca. Maksimal 200 karakter, batas dari Roblox.

Mau coba bikin link sendiri? Pakai generator share link.

Pasang di Roblox · langkah 4

Pembelian Robux

Setiap developer product yang dibeli lewat ProcessReceipt dilaporkan ke server. Game pass sengaja tidak dihitung.

!
Roblox cuma mengizinkan satu ProcessReceipt per game

Di game ini pemiliknya ReceiptService. Jangan bikin handler baru; cukup tambahkan satu baris di handler yang sudah ada.

Satu baris di ReceiptService

Panggil setelah handler produk mengembalikan true (item sudah tersimpan permanen) dan sebelum return PurchaseGranted:

ReceiptService · potongan
local AffiliateReport = require(game:GetService("ServerScriptService").Server.AffiliateReport)

MarketplaceService.ProcessReceipt = function(info)
	-- ... cek DataStore, cari player, jalankan handler produk seperti biasa ...
	local result = handler(player, info)

	if result == true then
		-- laporkan ke afiliasi. Fire-and-forget: tidak menahan pembelian, tidak pernah error ke sini.
		AffiliateReport.Robux(info)
		return Enum.ProductPurchaseDecision.PurchaseGranted
	end
	return Enum.ProductPurchaseDecision.NotProcessedYet
end

Transfer Robux antar pemain (RobuxTransferService, BindReceiptHandler) sengaja tidak dilaporkan.

Kalau server afiliasi lagi mati?

Pemain tetap dapat barangnya. Receipt yang gagal dilaporkan diparkir di DataStore AffiliatePending_v1, dan AffiliateService memanggil AffiliateReport.FlushPending() tiap 5 menit untuk mengirim ulang.

Kenapa aman kalau dikirim dua kali?

Server mengenali pembelian dari PurchaseId, yang unik dari Roblox. Kirim ulang dengan PurchaseId yang sama cuma balas duplicate: true, komisi tidak dobel. Jadi kalau ragu, kirim saja.

Yang dikirim ke server

AffiliateReport.Robux mengambil semuanya dari info: PurchaseId, PlayerId, ProductId, CurrencySpent (Robux kotor sebelum potongan), dan PlaceIdWherePurchased. Di Studio CurrencySpent selalu 0, jadi script mengambil harga dari katalog produk (priceSource = "product_info"). Server yang memotong fee 30% dan mengkonversi ke Rupiah. Lihat rincian di referensi endpoint.

Pasang di Roblox · langkah 5

Donasi bagi-bagi

Donasi Rupiah dari luar Roblox. Server perlu tahu donasi itu milik spender yang mana.

Alurnya: donatur kirim bagi-bagi → worker menerima webhook → MessagingService topic Donation → DonationService (dedupe per server, tebak username) → DonationBoardService._OnDonation → Record() lewat UpdateAsync (dedupe lintas server, satu pemenang) → AffiliateReport.Donation. Kenapa lewat game? Karena game yang paling tahu siapa player yang sedang online, jadi pencocokan donatur lebih akurat.

  1. Dua baris di DonationBoardService._OnDonation

    Jalur ok (server ini pemenang dedupe, userId ter-resolve) → AffiliateReport.Donation(event, userId, name). Jalur userId == nil → AffiliateReport.Donation(event, nil, username) supaya tetap masuk antrian Unmatched di dashboard.

  2. Bentuk event yang dibaca

    Field pendek dari worker: id, n (nama donatur), a (Rupiah), m (pesan), t (waktu), src. Yang wajib cuma id dan a.

  3. Donasi simulasi dilewati

    Event dengan src = "simulate" (dari Simulate()) tidak dilaporkan di server live, hanya diteruskan di Studio ke map tes.

Kalau player-nya nggak ada di server?

Server menebak dari beberapa petunjuk, urut prioritas: field username, nama donatur, sebutan @nama atau un: nama di pesan, lalu kata pertama pesan. Tebakan hanya dicocokkan ke spender yang sudah pernah join map kamu. Orang Roblox asing tidak dibuat otomatis.

Kalau tetap nggak ketemu, donasi masuk antrian Unmatched di dashboard (menu Spend, filter status unmatched). Owner tinggal pilih spender yang benar, komisi langsung dihitung ulang dengan rate saat donasi terjadi.

i
Jalur cadangan tanpa game

Worker juga boleh langsung memanggil POST /webhook/bagibagi di server afiliasi. Dua jalur boleh nyala bersamaan, karena server mengenali donasi dari id-nya, jadi tidak dobel. Detail di referensi endpoint.

Pasang di Roblox · langkah 6

Tes & pastikan jalan

Urutan cek dari yang paling gampang.

  1. Tes join dari Studio

    Pastikan secret AF_STUDIO menunjuk ke map tes dan Studio diberi akses secret. Tekan Play; script langsung mengirim join. Buka dashboard map tes → Spenders, akun kamu harus muncul. Di jendela Output Studio, laporan yang sampai dicetak [AffiliateReport] terkirim /ingest/join -> HTTP 200; kegagalan dicetak sebagai warn dengan awalan yang sama.

  2. Tes kode referral di game yang sudah publish

    LaunchData tidak bisa disimulasikan di Studio. Publish game, lalu buka share link salah satu admin dari akun Roblox lain (bukan akun admin itu sendiri). Cek Spenders: kolom referrer harus terisi.

  3. Tes tombol "Undang teman"

    Masuk dengan akun admin yang roblox_user_id-nya tercatat di dashboard: tombol muncul di kiri bawah. Klik, pilih teman, teman masuk lewat notifikasi undangan → di Spenders teman itu terikat ke admin, dan portal admin menampilkan "berhasil". Ulangi dari admin lain ke teman yang sama → pengundang kedua dapat notifikasi "sudah terikat ke admin lain".

  4. Tes pembelian

    Beli developer product di game yang sudah publish (Robux benar-benar terpotong, pakai produk murah). Cek Spend: event Robux muncul dengan status attributed kalau pembelinya masuk lewat link, atau unattributed kalau organik.

  5. Tes tanpa game pakai curl

    Buat memastikan server dan key benar, kirim langsung dari terminal. Pakai pembuat payload untuk menyusun perintahnya.

Halaman Flow di dashboard merangkum semua ini jadi checklist otomatis: join pertama, atribusi pertama, Robux pertama, bagi-bagi pertama, komisi pertama, payout pertama. Kalau ada join dengan kode yang tidak dikenal, halaman itu juga memperingatkan.

    Endpoint API

    POST/webhook/bagibagi cadangan

    Untuk proxy yang mau lapor langsung tanpa lewat game. Autentikasi pakai header x-webhook-secret (atau ?secret=), atau HMAC-SHA256 dari body mentah di header x-signature. Diset lewat WEBHOOK_SHARED_SECRET / WEBHOOK_HMAC_SECRET di .env. Kalau dua-duanya kosong, endpoint terbuka (hanya untuk development).

    Payload mengikuti bentuk webhook bagi-bagi: id atau transaction_id, name atau donator_name, amount, message, username, created_at. Field lain diabaikan tapi disimpan mentah.

    401x-map-key wajib atau map key tidak valid / map nonaktif. Cek key, cek map masih aktif, cek belum di-rotate.

    Referensi

    Status event

    Setiap laporan spend punya satu status. Terlihat di dashboard menu Spend.

    attributed
    Spender punya admin pengajak. Komisi dihitung dan masuk saldo admin.
    unattributed
    Spender organik, tidak lewat link siapa pun. Dicatat untuk analitik saja, komisi 0.
    unmatched
    Donasi bagi-bagi belum ketemu spender-nya. Menunggu owner cocokkan manual.
    void
    Dibatalkan owner (misal refund). Komisi yang sudah masuk dibalik di ledger. Tidak ada yang dihapus.
    Referensi

    Masalah umum

    Gejala di kiri, penyebab dan obatnya di dalam.

    Output Studio: "Http requests are not enabled"

    HTTP Requests belum dinyalakan. Game Settings → Security → Allow HTTP Requests = ON, lalu publish ulang.

    Output: "[AffiliateReport] /ingest/join ditolak HTTP 401"

    Key salah, map dinonaktifkan, atau key sudah di-rotate. Ambil key baru lewat Rotate key di Config → Maps, update nilai secret AF (atau AF_STUDIO) di Creator Dashboard, lalu restart server.

    Output: "[AffiliateReport] ... ditolak HTTP 503"

    Belum ada rate komisi. Config → Rate → buat rate. Setelah itu laporan berikutnya langsung diterima. Pembelian yang sempat gagal dilaporkan dikirim ulang oleh FlushPending tiap 5 menit.

    Output: "[AffiliateReport] ... gagal setelah 3 percobaan"

    Server tidak bisa dijangkau dari Roblox. Pastikan alamatnya https publik, bukan localhost atau IP lokal. Coba buka alamat itu dari HP dengan data seluler. Pastikan juga tidak ada garis miring ganda: BASE_URL tanpa / di akhir.

    Output: "[ApiAuth] secret AF tidak terbaca"

    Secret belum dibuat, namanya beda, atau Studio belum diberi akses. Buat AF (dan AF_STUDIO untuk Studio) di Creator Dashboard → Secrets. Selama secret tidak terbaca, semua laporan afiliasi mati tapi game jalan normal.

    Join masuk, tapi referrer kosong padahal pakai link

    Tiga kemungkinan. Pertama, tes dilakukan di Studio: LaunchData tidak ada di Studio, harus di game yang sudah publish. Kedua, player masuk dari tempat lain (daftar game, undangan teman) bukan dari link. Ketiga, player memakai akun admin itu sendiri: self_referral.

    Cek halaman Flow: kalau ada peringatan "kode tidak dikenal", berarti link-nya salah format atau kodenya tidak ada.

    Spender sudah punya referrer, tapi bukan admin yang saya harapkan

    First-touch. Dia sudah pernah masuk lewat link admin lain sebelumnya, dan itu yang dihitung selamanya. Riwayat semua kode yang pernah dia bawa ada di detail spender.

    Pembelian Robux terjadi, tapi tidak muncul di dashboard

    Pastikan AffiliateReport.Robux(info) benar-benar dipanggil di cabang result == true di ReceiptService. Kalau game punya dua handler ProcessReceipt, hanya yang terakhir di-assign yang jalan. Cek juga bahwa itu developer product, bukan game pass, dan bukan transfer Robux antar pemain.

    Balasan "duplicate: true"

    Bukan error. Pembelian atau donasi dengan ID yang sama sudah pernah dicatat. Roblox memang sering memanggil ProcessReceipt lebih dari sekali.

    Donasi bagi-bagi statusnya unmatched terus

    Server tidak menemukan spender yang cocok. Penyebab paling sering: donatur belum pernah join map kamu (jadi belum ada di daftar spender), atau nama yang dia tulis beda dengan username Roblox-nya. Lihat candidates di balasan untuk tahu nama apa saja yang dicoba.

    Solusinya: cocokkan manual di dashboard, atau minta donatur menulis username Roblox di pesan donasi, misalnya @namaakun.

    Komisi 0 padahal statusnya attributed

    Cek rate saat transaksi. Kalau komisi 0%, atau untuk Robux kursnya 0, hasilnya memang 0. Pembelian yang sangat kecil juga bisa 0 karena pembulatan ke bawah: 1 Robux × 70% = 0 Robux net.

    Saya salah catat, mau hapus

    Tidak ada tombol hapus, sengaja. Pakai Void di event tersebut. Komisi yang sudah masuk dibalik, dan semuanya tercatat di Audit.

    Referensi

    Kamus istilah

    Kata-kata yang muncul di dashboard dan di panduan ini.

    Owner
    Kamu, pemilik sistem. Login ke dashboard, atur rate, map, admin, dan payout.
    Admin
    Orang yang mengajak player ke map lewat share link dan dapat komisi.
    Spender
    Player yang pernah masuk ke map dan tercatat. Bisa punya admin pengajak (referrer) atau tidak.
    Kode referral
    6 karakter unik milik admin, misalnya K7PQ2M. Ditempel di link sebagai ref_K7PQ2M.
    LaunchData
    Teks yang Roblox selipkan ke game saat player masuk lewat link games/start. Di sinilah kode referral dibawa.
    Ingest key
    Password map untuk mengirim laporan ke server, berawalan mk_. Disimpan sebagai Roblox Secret AF, dibaca lewat ApiAuth.affiliateKey().
    Place ID
    Angka ID tempat (place) di Roblox. Dipakai di share link.
    First-touch
    Aturan bahwa spender terikat ke admin pertama yang kodenya dia pakai, selamanya.
    Developer product
    Barang yang bisa dibeli berulang di game pakai Robux. Yang dihitung komisi. Game pass tidak.
    Bagi-bagi
    Layanan donasi Rupiah dari luar Roblox. Diteruskan ke game lewat proxy dan MessagingService.
    Ledger
    Buku besar komisi admin. Saldo admin = jumlah semua baris ledger (earn, reversal, payout).
    Payout
    Pembayaran saldo admin, biasanya bulanan. Owner generate lalu tandai sudah dibayar.
    bps
    Basis poin. 100 bps = 1%, 1000 bps = 10%. Cara server menyimpan persen supaya tidak ada pecahan.
    Idempoten
    Kirim berkali-kali hasilnya tetap satu. Server begini untuk pembelian (by PurchaseId) dan donasi (by id).
